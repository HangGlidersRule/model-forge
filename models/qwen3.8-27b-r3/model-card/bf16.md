# Darkstar-Qwen3.8-27B-Abliterated-BF16

> **Reduced-refusal model.** A refusal-direction edit was deliberately applied. See the safety
> caveat below.

Private checkpoint repository: `HangGlidersRule/Darkstar-Qwen3.8-27B-Abliterated-BF16`.

## Summary

BF16 derivative of `Qwen/Qwen3.8-27B` produced by one reproducible, audited refusal-direction
projection ("abliteration"). It is the editable source artifact from which the Darkstar
Abliterated ModelOpt NVFP4 build is quantized. No quantization is applied here.

## Edit summary

- Direction: normalized float32 harmful-minus-harmless residual difference measured at
  language-model layer 38 (hidden dim 5120), seed 42.
- Corpora: `mlabonne/harmful_behaviors@01cead01398926d81f7c52bdb790ee8cf77ebba7` (128 harmful) and
  `mlabonne/harmless_alpaca@02c6a92cfcf11bb0c387334f8146d149d65b587f` (128 harmless), deterministically
  normalized and deduplicated.
- Targets: exactly 131 residual-writing tensors — 16 self-attn `o_proj`, 48 linear-attn `out_proj`,
  64 MLP `down_proj`, `embed_tokens`, and the two corresponding MTP residual writers.
- Projection `W' = W - r(rᵀW)` applied in float32, cast back to source dtype.
- Vision tower (333 tensors) untouched; all 15 MTP tensors preserved. Max normalized residual
  leakage ≈ `0.000195`.

## Intended use

- Research on refusal behavior, activation steering, and quantization effects.
- A BF16 base for downstream quantization or further study.

## Safety caveat (reduced refusal)

This model has had its refusal direction **deliberately reduced**. In the fresh 200-prompt harmful
suite it complied with 200/200 harmful prompts (0/200 refusals) and over-refused 0/83 safe prompts. It
will comply with many requests that the upstream model would refuse. It has **no added safety
mitigations**. Deploy only behind your own policy, filtering, and access controls, and only where doing
so is lawful. Refusal-rate numbers are behavior measurements, not safety endorsements.

## Limitations

- The R3 edit costs measured accuracy: full-denominator BF16 GPQA delta is `-11` questions / `-5.56`
  percentage points vs the Darkstar Base BF16 baseline (157/198 → 146/198).
- Quantization can introduce quality regressions not captured by GPQA.
- Only single-stream throughput is characterized; aggregate concurrent throughput is separate.

## Runtime requirements and example

- Runtime: vLLM `0.27.1`, compiled mode, Flash Attention, BF16 KV cache, context up to 126,144.
- Serve profile: MTP depth 11, 16K scheduler budget, `max_num_seqs=16`.

```bash
vllm serve HangGlidersRule/Darkstar-Qwen3.8-27B-Abliterated-BF16 \
  --served-model-name darkstar-qwen38-abliterated-bf16 \
  --kv-cache-dtype bf16 \
  --max-model-len 126144 \
  --max-num-seqs 16 \
  --max-num-batched-tokens 16384 \
  --enable-chunked-prefill \
  --compilation-config 2 \
  --speculative-config '{"method": "mtp", "num_speculative_tokens": 11}'
```

See [`containers/serve/docker-compose.yml`](../../../containers/serve/docker-compose.yml).
